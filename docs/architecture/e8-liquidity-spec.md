## 0. Decisions in one screen

| Topic | Decision |
|---|---|
| Series (E8-1) | `POST /ride-series` creates **every instance up front** in one transaction under the existing per-driver publish lock; each date is checked against the 4-per-day limit and skipped (reported) instead of failing the request. Series end ≤ 28 days, so instances may depart up to 28 days ahead (normal rides keep 14). `ride_series` holds **no geometry** (the preview route is copied to each ride). Cancel = one ride as today, or all future instances (ADR 0039) |
| Alerts (E8-2) | `POST /alerts` stores origin/destination, a date **or** weekdays, a local time and a ±window. Matching runs in a **tick step**, not in the publish request: `app.match_ride_alerts` takes new rides (`alerts_checked_at IS NULL`), finds alerts near the route (GiST), and confirms each with `app.match_rides(…, p_ride_id)` (same rules as search). `ride_alert_hits (alert_id, ride_id)` PK = **once per ride**. One notification per alert per tick (series instances grouped). Max 5 active, 14-day expiry, **deleted** on expiry (ADR 0036) |
| Auto-accept (E8-3) | `rides.auto_accept`. In `POST /bookings`, after the insert and **under the same ride lock**, an eligible requester (visible rating ≥ 4.0, or "New" with < 3 visible ratings) is confirmed by the same routine as approve (seat +1, relock). Blocks already fail the request with `BLOCKED`. Only new requests are auto-confirmed (ADR 0037) |
| Web push (E8-4) | Own minimal RFC 8291 (aes128gcm) + RFC 8292 (VAPID) sender on WebCrypto and the existing `jose`, verified by the RFC test vector; no `web-push` npm. Push is its **own outbox row** (`channel='push'`) next to the email row, dispatched in a separate tick step with no daily cap. Lifecycle templates: email always, push in addition. Alert matches: push first, email only without a subscription or after the push finally fails. Payload = title, body, path, tag: **area labels and times only, no names** (ADR 0038) |
| Monthly stats (E8-5) | `GET /me/stats/month` from one STABLE SQL function; driver line "This month you shared X RON of fuel costs" |
| Privacy | Alerts deleted at expiry (`run_retention`) and on `DELETE /me` (`scrub_account`); push subscriptions deleted on `DELETE /me` and on 404/410; series deleted 90 days after their end. New geometry columns join the pgTAP 009 catalog guard. Push endpoints restricted to known push services (no SSRF) |
| Not in E8 | Ride-wanted posts (E8-6), editing a series, alert renewal, per-alert notification caps, push for `rating_prompt*` / admin / privacy templates, Realtime |

## 2. E8-1 Ride series (ADR 0039)

**Rules** (`_shared/domain/series.ts`, pure): `weekdays` unique ISO 1..7, at least one; `departureTime` `HH:MM` 00:00..23:59; `startsOn` default today (local), today ≤ startsOn ≤ today + 14; `startsOn ≤ endsOn ≤ today + 28` (`SERIES_MAX_DAYS`); `seriesDates(startsOn, endsOn, weekdays)` → ascending local dates (≤ 29). Per date: `departureAt = bucharestLocalToUtc(day, time)`; if `bucharestTime(departureAt) ≠ time` (DST gap) → skip `INVALID_TIME`; if `departureAt < now + 15 min` → skip `DEPARTURE_TOO_SOON`.

**`services/series.ts` `createSeries`** (one tx): vehicle and seats checks as `publishRide` → `lockDriverPublishing` (one advisory lock for the whole series) → insert `ride_series` → for each date: `countDriverRidesBetween(day)` ≥ 4 → skip `DAILY_RIDE_LIMIT`; else `insertRideFromPreview` (extended with `seriesId`, `autoAccept`; same preview reused, same energy price snapshot) + `ride_published` event. Instances inserted earlier in the transaction count toward their day. No instance created → roll back; all skips `DAILY_RIDE_LIMIT`-or-too-soon → `409 DAILY_RIDE_LIMIT`; the date set itself empty → `400 fields.endsOn = no_dates`. Preview unknown/expired → `PREVIEW_EXPIRED` (before any insert).

**`cancelSeries`** (one tx): series of the caller (else `404`), `active` (else `409 INVALID_STATE`) → for every `published` instance with `departure_at > now`, in departure order: `selectOwnerRide(…, lock)` + `cancelRideTx(…, 'driver', isLateRideCancel)` (cascade, emails, reliability event when late, exactly as a single cancel) → series `cancelled`. Cancelling a single instance stays `POST /rides/{id}/cancel` and leaves the series active.

## 3. E8-2 Ride alerts (ADR 0036)

**Rules** (`_shared/domain/alerts.ts`): points rounded to 5 decimals, inside `COVERAGE_BBOX`, ≥ 1 km apart (`fields.from|to = outside_coverage`, `fields.to = too_close`); labels NFC, trimmed, 1..80; `schedule` is `{kind:'date', date}` (today..today + 14 local) or `{kind:'weekly', weekdays}`; `time` `HH:MM`; `windowMin ∈ SEARCH_WINDOWS_MIN`. `alertExpiresAt`: weekly = `created + 14 d`; date = `min(created + 14 d, local(date, time) + window)`.

**`services/alerts.ts` `createAlert`** (one tx): lock the caller's profile `FOR NO KEY UPDATE` (E6 lock lesson) → identical active alert (same rounded points, schedule, time, window) → return it with `200` → count active (`expires_at > now`) ≥ `ALERTS_MAX_ACTIVE` (5) → `409 ALERT_LIMIT` → insert → event `alert_created {alertId, kind, windowMin, fromArea, toArea}` (area of each point via `app.area_for`) → `201`.

**Tick step `matchAlerts`** (one tx, `ALERT_MATCH_BATCH = 50` rides): `select * from app.match_ride_alerts(now, 50)` → group by `alert_id`; per alert the soonest ride is the subject, `moreCount = hits − 1` → outbox `ride_alert_match {alertId, rideId, departureAt, pickupArea, dropoffArea, moreCount}` inserted **push-first** (`insertPushFirstOutbox`: `channel = 'push'` when the user has a subscription, else `'email'`) → `UPDATE ride_alerts SET last_notified_at = now, matches_sent = matches_sent + 1` → one `alert_matched {alertId, rideId}` event per hit. Latency: ride published → next tick (≤ 60 s) → dispatched in the same tick: well under the 5-minute target.

## 4. E8-3 Auto-accept (ADR 0037)

`_shared/domain/autoAccept.ts`: `isAutoAcceptEligible({ ratingCount, ratingAvg })` = `ratingCount < MIN_RATINGS_TO_SHOW` ("New") **or** `ratingAvg ≥ AUTO_ACCEPT_MIN_RATING` (4.0), visible ratings only (`repo/ratingSummary.ts`, `visible_at ≤ now`).

**`createBooking` change:** `lockRide` also selects `auto_accept`. After `insertBooking` (all E4 guards unchanged, so `BLOCKED`, `RIDE_FULL`, `NO_LONGER_MATCHES` still win): if `ride.auto_accept` and eligible → `confirmLocked(db, ride, bookingId, now, { auto: true })`, a routine **extracted from `approveBooking`** into `services/bookingConfirm.ts` and used by both (guarded `confirmBooking`, `adjustSeatsBooked +1` with the `23514 → RIDE_FULL` backstop, relock of all confirmed prices, `auto_confirmed = true` when auto). Outbox: `booking_auto_confirmed {bookingId, rideId, departureAt, pickupArea, dropoffArea}` → driver **instead of** `booking_requested`; no email to the passenger (they see it on screen). Events: `booking_requested` then `booking_confirmed {…, responseSeconds: 0, auto: true}`. An idempotent replay returns the current view. Not eligible → the E4 flow (requested, 30-minute expiry).

**`PATCH /me/rides/{id}`:** lock the ride (driver only, else `404`), `published` and not departed (else `409 INVALID_STATE`), set `auto_accept`. Pending requests are **not** confirmed by switching on.

## 7. API contract (`_shared/contracts/liquidity.ts`, re-exported from `index.ts`)

Gates as architecture §8: every route needs an active account; writes also need consent (`CONSENT_REQUIRED`). Series also `PROFILE_INCOMPLETE`, `VEHICLE_REQUIRED`. Ids that are not UUIDs → `404`.
